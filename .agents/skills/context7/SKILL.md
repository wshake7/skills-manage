# Context7 Skill

This skill enables an AI coding agent to augment its knowledge with live, up‑to‑date library documentation via **Context7**. Context7 provides an MCP server (preferred) or a CLI to fetch documentation snippets directly from `context7.com`.

## Prerequisites

- **Node.js** (to install packages or run `npx`).
- A **Context7 API key** stored as `CONTEXT7_API_KEY` (sign up at [context7.com](https://context7.com)).
- The agent should run `ctx7 setup` interactively once to choose MCP or CLI + Skills mode (see setup).

## Primary Workflow (MCP Mode)

When the Context7 MCP server is configured (e.g., via `.mcp.json` generated by `ctx7 setup`), the agent possesses a direct tool to query documentation. Use it **preferentially** for any library documentation request:

1. **Receive a user query** mentioning a library/package (e.g., “How do I use React Router v7 data loaders?”).
2. **Invoke the Context7 MCP tool** (e.g., `context7_get_library_docs` or `ctx7_search`) with the library identifier (e.g., `/reactrouter/react-router`) and the specific question.
3. **Integrate the returned snippet** into the answer, always citing Context7 as the source.
4. If the MCP tool returns an error or no results, **fall back** to the CLI workflow below.

## Fallback Workflow (CLI Mode)

If the MCP server is not available but the Context7 CLI is installed (via `npm install -g ctx7@latest` or `npx ctx7@latest`), use the CLI to retrieve documentation:

```bash
npx ctx7 doc <library_id> "<query>"
```

Example:
```bash
npx ctx7 doc /reactrouter/react-router "How to define a loader function"
```

- Replace `<library_id>` with the Context7 library slug (e.g., `/websites/reactrouter`).
- Capture the terminal output and use it in the answer.
- If `npx ctx7 doc` is not recognized, ensure the CLI is installed or try `ctx7 search <library_id> "<query>"`.

## Setup (`ctx7 setup`)

The interactive setup configures the agent’s environment:

```bash
npx ctx7 setup
```

Choose **MCP server mode** to write an `.mcp.json` (or agent‑specific MCP config) and the `context7‑mcp` skill. This mode gives the agent direct MCP access.

Choose **CLI + Skills mode** to install the `docs` skill that internally calls `ctx7` CLI. The agent then uses the skill’s commands rather than raw CLI calls.

After setup, restart the coding agent so it picks up the new configuration.

## Fallback When Context7 Is Not Configured

If neither MCP nor CLI is installed and `CONTEXT7_API_KEY` is not set:

- **Inform the user** that live documentation via Context7 is unavailable.
- **Suggest** running `ctx7 setup` or manually adding the MCP server entry (with the API key).
- **Fall back to web search** (e.g., `web_search` tool) for the documentation query, but note that results may be outdated or incomplete.
- **If a library’s docs are already cached** in the agent’s training data, use that with a warning about possible staleness.

## GitHub Actions Integration (for Maintainers)

To keep documentation fresh for your own libraries, add a workflow file (`.github/workflows/context7-refresh.yml`) that triggers a refresh on each push:

```yaml
name: Refresh Context7 Docs
on:
  push:
    branches: [master]
jobs:
  refresh:
    runs-on: ubuntu-latest
    steps:
      - name: Trigger Context7 Refresh
        run: |
          curl -s -X POST https://context7.com/api/v1/refresh \
            -H "Content-Type: application/json" \
            -H "Authorization: Bearer ${{ secrets.CONTEXT7_API_KEY }}" \
            -d '{"libraryName": "/${{ github.repository }}"}'
```

## Installing Additional Skills from GitHub

To equip the agent with other skills maintained in a repository (e.g., `/anthropics/skills`):

```bash
ctx7 skills install /anthropics/skills
```

Use `--all` to install all skills without prompts, or provide a specific skill name.

> **Note:** This skill itself is a runtime‑adapter skill. It should be used with the Context7 MCP server (preferred) or the Context7 CLI as the runtime. All commands assume `ctx7` is available via `npx` or as a global binary.
