# UI/UX Pro Max Skill

Automatically generate production-grade design systems (colors, typography, spacing, shadows, components) for any project. Use the generated tokens and component specs to build consistent, beautiful, accessible UIs quickly.

## Prerequisites

- **Python 3.9+** – required for the design system generator (`design_system.py`)
- **Node.js 18+** – optional, only if you want to use the `uipro-cli` installer

## Quickstart (for Codex users)

Run the installer to append this skill to your project’s *AGENTS.md*:

```bash
npx uipro-cli init --ai codex
```

After restarting Codex, the skill becomes available. If you already have a `design-system/` folder, the skill will read and use it directly.

## How It Works

When a user asks you to build a page or component:

1. **Check for an existing design system.** Look for a folder named `design-system/` in the project root.  
   - If it exists, read `design-system/<brand>/MASTER.md` and any page-specific overrides in `design-system/<brand>/pages/<page-name>.md`.
   - If it does **not** exist, generate one using the steps below.

2. **Generate a design system** (if needed). Use the `DesignSystemGenerator` Python class from the bundled `design_system.py` script:

   ```python
   from design_system import DesignSystemGenerator

   generator = DesignSystemGenerator()
   design_system = generator.generate(
       "e-commerce luxury fashion",
       "LuxStore"
   )
   ```

   The first argument is the product/vibe description, the second is the brand name (used for folder naming).

3. **Persist the design system** with `persist_design_system`:

   ```python
   from design_system import persist_design_system

   # Save MASTER.md only
   persist_design_system(design_system, output_dir=".")

   # Save MASTER.md + a page override (e.g., for a checkout page)
   persist_design_system(design_system, page="checkout", output_dir=".")
   ```

   This creates a `design-system/luxstore/` folder containing:
   - `MASTER.md` – global design tokens, CSS variables, component specs, anti-patterns, pre-delivery checklist.
   - `pages/checkout.md` (when a page is provided) – page-specific overrides that take priority.

4. **Use the design system when writing code.** Always refer to the tokens defined in the master file:
   - Colors: `var(--color-primary)`, `var(--color-secondary)`, etc.
   - Spacing: `var(--space-sm)`, `var(--space-md)`, …
   - Shadows: `var(--shadow-md)`, …
   - Typography: font family, sizes, and weights from the `MASTER.md` table (import the Google Fonts URL if present).
   - Components: buttons, cards, inputs, modals – follow the exact CSS specs provided.

5. **Respect the override pattern.** Before building a specific page, check if a page file exists. If it does, its rules override the master rules for that page alone.

## Page Override Precedence

```
design-system/luxstore/MASTER.md       ← global rules
design-system/luxstore/pages/*.md      ← page-specific overrides (higher priority)
```

Example: on the *Checkout* page, the master file sets `--color-primary: #2c3e50;` but `pages/checkout.md` overrides it to `--color-primary: #1a252f;`. Use the override value for that page.

## Anti-Patterns (what NOT to do)

- ❌ Hard-coding colors, spacing, or typography values – always use tokens.
- ❌ Ignoring page overrides – always read the page-specific file when it exists.
- ❌ Using inline styles instead of the generated CSS classes/variables.
- ❌ Skipping the pre-delivery checklist from `MASTER.md`.

## Pre-Delivery Checklist (always run before finishing a UI task)

- [ ] All colors reference CSS custom properties from the design system.
- [ ] Spacing uses the defined `--space-*` tokens (no magic numbers).
- [ ] Typography matches the specified font families and sizes.
- [ ] Shadows use the documented `--shadow-*` variables.
- [ ] Component classes (`.btn`, `.card`, `.modal`, etc.) match the specs in `MASTER.md`.
- [ ] If building a specific page, the correct override file (if any) has been applied.

## Example Workflow

**User:** "Build a landing page for a SaaS product called TaskFlow."

**AI (following this skill):**

1. Look for `design-system/` → not found.
2. Run Python to generate a design system:
   ```python
   from design_system import DesignSystemGenerator
   ds = DesignSystemGenerator().generate("SaaS productivity tool", "TaskFlow")
   persist_design_system(ds, output_dir=".")
   ```
3. Read `design-system/taskflow/MASTER.md` and note the color palette, space tokens, button styles, etc.
4. Build the landing page HTML/CSS using only those tokens.
5. Verify against the pre-delivery checklist.

This skill works with any AI-powered coding assistant. The files generated by `persist_design_system` are plain Markdown and CSS, so you can manually inspect and tweak them if needed.
